## 1. 模块名称

**M1 核心账务** —— 分类、账户、统一业务事件、资金变动、收入、支出、内部转账、基础统计

## 2. 本次范围

| 能力 | 交付内容 |
|---|---|
| 账户 | 列表（含搜索/类型/状态筛选）、新增、编辑、停用、详情（余额 + 流水）、按币种余额汇总 |
| 余额计算 | 后端确定性计算：**当前余额 = 期初余额 + Σ(已确认事件的资金变动净额)**；草稿/取消/冲销不计入 |
| 统一业务事件 | 列表（9 类筛选）、草稿创建、确认、冲销、详情（含资金变动） |
| 收入 / 支出 | 新增表单（类型/金额/账户/分类/发生时间/商户/备注）、草稿→确认→冲销全链路 |
| 内部转账 | 转账表单、转账组、转出/转入双事件、手续费、跨币种汇率确认、冲销 |
| 基础统计 | 台账统计接口 + 工作台真实数据（净资产、收支、结余、多币种分组、趋势图、收支对比图） |
| 分类 | 沿用 M0 的六域分类；本模块补齐**分类域与事件类型的匹配校验** |

## 3. 不包含范围（明确不做，避免半成品或假数据）

- 资产 / 不动产 / 车位 / 车辆 / 贵金属（M2）
- 负债 / 房贷 / 车贷 / 信用卡（M3）
- 投资账户 / 持仓 / 交易（M3）
- 房产租赁 / 对账（M4）
- 智能录入 / OCR（M5）
- 工作台跨模块完整卡片、洞察图表（M6）
- 提醒与通知（M8）
- **不做**：盘点、位置管理、导出、后台任务、Worker、消息队列、独立 AI 菜单

> 关键约束落实：`asset_acquire` / `liability_repay` / `investment_buy` / `rent_received` 等
> 需要关联对象的类型，**在所属模块交付前不允许创建**，接口返回 409 并明确告知属于哪个模块。
> 这样避免产生无法追溯的孤儿数据（依据《18 §6》「业务模块可以先建立关联字段，但必须在关联模块完成后再启用完整操作」）。

## 6. API 与错误码

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/ledger/accounts` | 账户列表（keyword / account_type / status 筛选），返回余额 |
| POST | `/api/v1/ledger/accounts` | 新增账户 |
| GET | `/api/v1/ledger/accounts/{id}` | 账户详情（余额 + 流水） |
| PUT | `/api/v1/ledger/accounts/{id}` | 编辑账户（带 `version` 乐观锁） |
| DELETE | `/api/v1/ledger/accounts/{id}` | 停用账户（需一次性确认令牌 + 原因） |
| GET | `/api/v1/ledger/events` | 流水列表（direction / account / category / status / source / keyword / 日期区间 / 金额区间 / 分页） |
| POST | `/api/v1/ledger/events` | 创建草稿 |
| POST | `/api/v1/ledger/events/{id}/confirm` | 确认（事务内生成资金变动 + 审计） |
| POST | `/api/v1/ledger/events/{id}/reverse` | 冲销（必须填原因） |
| GET/POST | `/api/v1/ledger/transfers` | 转账列表 / 创建转账 |
| POST | `/api/v1/ledger/transfers/{id}/reverse` | 冲销转账（组内事件一并冲销） |
| GET | `/api/v1/ledger/summary` | 台账基础统计 |

新增/复用的错误码：`STATE_INVALID`(409 未交付类型)、`VERSION_CONFLICT`(409)、`VALIDATION_ERROR`(422 字段级)、`FORBIDDEN`(403)。

## 7. 关联关系

```text
家庭 ──┬─ 账户 ──┐
       ├─ 分类 ──┤
       ├─ 成员 ──┼──▶ 业务事件 ──▶ 资金变动 ──▶ 账户余额
       └─ 附件   │         ▲
                  └─────────┴── 转账组（转出事件 + 转入事件 + 手续费事件）
```

- 事件可直接关联 `account_id` / `category_id` / `member_id`（本模块已启用），其余关联字段（asset / liability / investment / lease）保持预留。
- 转账组通过 `out_event_id` / `in_event_id` / `fee_event_id` 与统一事件双向绑定，冲销时整组生效。
- 分类域与事件类型强制匹配：收入只能用 `income` 域分类，支出只能用 `expense` 域分类。

## 8. AI 接入与禁止动作

- 工作台与账户/流水页均提供 AI 入口，携带当前页面上下文（路由、期间、币种、账户 ID）。
- AI 只能读取 `/dashboard/snapshot`、`/ledger/summary` 等确定性统计结果，**不得自行计算余额或净资产**。
- 禁止：自动确认流水、自动创建转账、自动修改账户余额、绕过用户确认写入正式台账。
- 本模块未引入任何新 AI 工具，沿用 M0 的 13 项工具白名单契约。

## 9. 浅色 / 深色效果

## 12. 删除二次确认

- 停用账户：统一 `ConfirmDialog` + 服务端一次性确认令牌（`account.archive`）+ 必填原因。
- 冲销事件 / 冲销转账：统一确认弹窗 + 必填原因，按钮文案为「确认冲销」。
- 有资金变动的账户**不允许删除**，接口返回 409 并提示只能停用；有流水的账户**不允许改币种**（返回 409，字段级提示）。

## 16. 已知问题

1. **可用余额 = 当前余额**：额度/透支模型属于信用卡（M3），当前未建模，接口已给出该字段并在报告中说明。
2. **净资产目前仅含账户口径**：资产与负债模块交付后并入，`net_worth.note` 已在接口中明示，避免误读。
3. **趋势图按月计算**：家庭级数据量下采用内存聚合，若未来单户流水达到十万级需要改为 SQL 聚合。
4. 工作台的「待处理提醒 / 未对账账户 / 临近账单 / 租金逾期」四项仍为 0，依赖 M4/M6/M8 模块。
