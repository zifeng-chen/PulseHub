## 8. AI 接入与禁止动作

- 四类适配器接口已就位并可测试；未配置时返回 `PROVIDER_NOT_CONFIGURED` 且**不阻塞任何记账、台账、统计与历史查询**。
- AI 工具白名单契约（13 项工具 × 中文名称 / 权限 / 数据范围 / 可否生成建议 / 可否写草稿 / 禁止动作）已通过 `GET /api/v1/ai/tools` 暴露。
- 调用优先级：权限检查 → 确定性工具 → 本地 AI → 可选第三方 AI。第三方 AI 默认关闭，启用需**二次确认令牌 + 云端外发总开关 + 外发字段预览 + 审计**；本地 AI 失败**不静默切换**。
- 禁止：调任意 SQL/URL/文件系统、直接写业务表、自动确认、自动改估值/余额/本金/交易/实收、自动下单转账删除、创建后台任务/导出/位置管理。
- AI 固定评测用例 12 条（净资产、资产占比、消费总额、收入来源、负债余额、贷款利息、投资损益、租金逾期、车辆年度费用、水电煤支出、数据缺失、多币种分组）已入库。

## 16. 已知问题与偏差

1. **本地运行底座**：本机无 MySQL 与 Docker，为让 M0 可被真实验收，数据层统一走 SQLAlchemy 2.x Async，**生产与产品向导固定 MySQL（aiomysql）**，本地开发/自动化测试默认使用 SQLite（aiosqlite）。首次启动向导新增了一个**仅非生产环境可用**的选项"使用内嵌开发数据库"（`use_embedded_dev_database`），生产环境调用直接 403。此项已在《V2.1 开发前理解报告》§0.3 记录。M0 未在真实 MySQL 上跑通连接测试路径（`POST /setup/database/test` 的 MySQL 分支已实现但无实例可验），M1 前建议在具备 MySQL 的环境补验一次。
2. **确认令牌存储**：为不新增文档未列出的数据表，确认令牌的"一次性"由签名 JWT + 进程内 `jti` 黑名单实现（5 分钟 TTL）。多进程或多副本部署时需改为共享存储（Redis/数据库），当前为单进程部署语义。
3. **`/settings/finance` 路由**：《23 §7》路由注册表未列出该路径，但《02》页面树与《08 §4》均定义了"财务口径"页，故按 02/08 实现，未视为新增。
4. **未交付模块的图标/图表**：工作台的资产结构、收支对比、净值趋势三张图在无数据时显示空状态占位（ECharts 组件已封装，随 M1/M2 填充）。
5. **备份范围**：附件目录做真实快照并计算校验值；数据库逻辑导出在本地 SQLite 下为文件级快照，生产 MySQL 场景下按《24 §2》交由部署工具链调用同一接口（M8 完善）。
6. **基础提醒规则**：《04 §3》步骤三提到"生成基础提醒规则"，`reminders` 表属 M8 提醒模块，故 M0 只在通知渠道中预置提醒类型开关，不建假提醒数据。
