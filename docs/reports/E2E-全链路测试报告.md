## 这套测试补的是什么缺口

- 后端 pytest（109 项）验证接口契约与计算，**不渲染页面**；
- 前端单测（12 项）只覆盖路由菜单派生逻辑；
- 两者都回答不了"点登录会不会跳转""金额显示对不对""某页会不会白屏"。

E2E 用真实 Chromium 打开真实页面，采集页面标题、正文、网络 5xx 与 JS 异常，并跨层比对接口与页面数据。

## E2E 首次运行发现并已修复的问题

1. 登录后「欢迎引导」为全屏模态弹窗，遮住整个首页 → 改为右下角非模态浮层（不遮挡、可关闭）。
2. 同一页面金额格式不一致（余额 `12,800.00` 带千分位，信用卡额度 `37654.33` 不带）→ 统一 `formatAmount`（千分位 + 家庭精度）。
3. 登录跳转前 `await` 主题接口、导航失败无兜底、懒加载 chunk 失败无恢复 → 均已加固。

## 覆盖范围

1. 首次启动初始化（数据库配置 → 管理员 → 家庭 → 财务口径 → 完成）
2. 真实浏览器登录：表单填写 → 提交 → 跳转 `/dashboard` → 首屏渲染 → 引导浮层不遮挡
3. 多视口巡检：PC 1440×900（36 页全量）、PC 1366×768（10 页关键）、移动 375×812（36 页全量）；检查渲染、横向溢出、占位文案、5xx、JS 异常
4. 响应式布局切换：PC 显示侧栏且隐藏底部导航；移动隐藏侧栏且显示底部导航
5. 表单级落库：抽屉内真实新增信用卡（分类联动出额度 / 有效期 / 账单日 / 还款日）→ 越界账单日被拦截 → 修正后保存并回显
6. **PC 功能级（6 个模块真实操作）**：流水新增支出草稿、资产登记（不动产·直接确认购置）、负债新增（房贷·关联房产）、投资账户新增、租约新增（关联房产）、分类新增；每项都校验抽屉关闭 + 列表回显 + 无 5xx/JS 异常
7. 账务状态机：流水 草稿 → 编辑 → 确认 → 冲销，每一步都校验列表中的真实状态
8. 对账流程：选账户 → 加载 → 填人工实际余额与差额说明 → 提交（生成调整事件）
9. 批量导入：CSV 预览（成功/错误/重复统计）→ 生成导入批次 → 批量确认 → 流水页可见
10. 数据备份：创建备份（二次确认 + 确认令牌）→ 备份列表出现记录 → 完整性校验 → 恢复预览 → 错误短语被拒 → 恢复请求记录为「已提交（待运维执行）」→ **断言数据未被改动**
11. OCR 附件上传：真实文件上传 → 附件列表可见（识别依赖外部 OCR 服务，未覆盖真实识别）
12. 提醒：六类提醒实时计算（groups）+ 发送链路（未配置渠道时 failed 计数，不 500）
13. 权限矩阵：新建只读成员 → 可登录、无「新增」入口、可读接口、写接口返回 403
14. 跨层一致性：信用卡可用额度计算、账户页金额与接口一致、金额精度改 4 位后页面同步
15. 路由守卫：清除登录态后访问受保护页应回登录页
