# 台账待办 / 待补齐的深链定位（2026-11-04）

## 摘要

台账总览的「待办时间轴」和「待补齐」原来只跳到一个**列表页首页**：点「4 项资产缺估值」进到资产页，一屏几十张卡，用户还得自己一张张找是哪 4 项。本次把「要处理的那几条」通过 `?focus=<id,...>` 带到目标页，目标页给对应行描边 + 呼吸效果，并自动滚到视野中间。

## 一、问题

| 位置 | 原来 | 问题 |
|---|---|---|
| 待办时间轴（today / week / later） | `router.push(q.to)` | 只带页面路径，不带具体对象 |
| 待补齐 | `router.push(g.to)` | 同上；缺口是**多条**，更需要指出是哪几条 |
| 提醒页「查看」 | `router.push(it.detail_to)` | 同上 |

后端其实早就把 `object_type` / `object_id` 冒出来了，但前端没用；`gaps` 更是只有 count，连 id 都没有。

## 二、设计

统一约定：**`?focus=id1,id2,...`**。

- 队列项（一般一条）→ `focus` 取该条对象的 id
- 缺口（可能多条）→ `focus` 取命中的全部 id（最多 60 条，避免整屏都在闪）
- 目标页拿到后：给匹配行加 `.focus-hit`，并把第一条 `scrollIntoView({block:'center'})`

为什么不用「直接打开详情抽屉」：一条缺口可能命中 4 条记录，抽屉只能开一条；而且自动弹抽屉会打断用户对列表整体情况的判断。描边高亮既能定位、又保留了上下文。

## 三、后端改动

### `app/services/workbench.py`

- 新增 `_focus(rows, attr="id", limit=60)`：把命中的记录 id 拼成逗号串
- 9 个 gap 全部补 `focus`：
  - `assets:unvalued` / `assets:stale` → 资产 id
  - `assets:ratio` → 取的是 `RealEstate.asset_id`（目标页列的是资产，不是不动产扩展表）
  - `accounts:reconcile` → 账户 id（对账页当默认选中项用）
  - `liabilities:fields` → 缺月供 ∪ 缺还款日的负债 id（去重）
  - `investments:quotes` / `leases:contract` / `leases:contact` / `leases:deposit` → 各自 id
- 队列项补 `focus`，取自提醒项的 `focus_id`
- 未归类流水：原来只 `COUNT`，现在顺带取最近 60 条 id（`order by occurred_at desc`），点进去能直接看到是哪几笔

### `app/services/reminders.py`

新增 `focus_id` 概念：**`object_id` 不一定等于目标页的主键**。

| 提醒 | object_id | 目标页 | focus_id |
|---|---|---|---|
| 租金应收 | 应收单 id | 租约列表 | **租约 id**（`lease_id`） |
| 信用卡账单 | 账单 id | 信用卡列表 | **卡 id**（`card_id`） |
| 还款 / 租约到期 / 资产维护 / 账户账单 | 对象 id | 对应列表 | 同 object_id |
| AI 建议（insight 类） | `"transactions"` 这类伪 id | 洞察页 | **空串**（只跳页面，不定位） |

`_item()` / `add()` 都接受 `focus_id`，默认 `None` = 沿用 `object_id`，显式传 `""` = 不定位。

## 四、前端改动

### 新增 `composables/use-focus-targets.ts`

- `focusLink(to, focus)`：纯函数，拼地址时保留目标页原有 query，清理空白/空段，最多 60 条
- `useFocusTargets()`：返回 `{ isFocused(id), reveal() }`
  - `focusIds` 用 `ref` 保存而不是直接跟随 query——流水页会把筛选写回 URL，一次 `replace` 就会把 `focus` 抹掉；只在「新值非空」时更新，页面自己清理 query 不会把高亮一起清掉
  - `reveal()` 等一次 `nextTick` 再 `scrollIntoView`，`prefers-reduced-motion` 下用 `auto` 而不是平滑滚动

### 新增全局样式 `styles/base.css`

`.focus-hit` 用 **outline** 而不是 box-shadow：卡片各自带玻璃投影，box-shadow 会互相覆盖；outline 不占布局、不改圆角，对卡片和表格行都安全。`scroll-margin-top: 96px` 避开吸顶头部。呼吸 3 次后停在常亮描边，滚回来还能看见目标。

### 接入的页面

| 页面 | 高亮目标 |
|---|---|
| `AssetsView` | `AssetCard` 行（class 透传到根 `<article>`） |
| `LiabilitiesView` | 负债卡片 |
| `InvestmentsView` | 投资账户卡片 |
| `LeasesView` | 租约卡片 |
| `AccountsView` | 账户卡片 |
| `CreditCardsView` | 卡片（同时匹配 `row.id` 与 `row.card.id`，兼容两种信用卡建模） |
| `TransactionsView` | 表格行（`AppDataTable` 新增 `rowClass` 能力） |
| `ReconciliationView` | 无列表，改为把 `focus` 第一个 id 当 `account_id` 预填并直接加载预览 |
| `RemindersView` | 「查看」按钮复用 `focusLink` |

`AppDataTable` 顺带新增 `rowClass?: (row: T) => string`，桌面表格行与移动端卡片同时生效。

## 六、已知边界

- **流水页是分页的**：`focus` 指向的流水如果不在当前页（默认第 1 页，按日期倒序），本页不会高亮。未归类流水通常就在最近几页，影响很小；要彻底解决需要后端支持「按 id 列表查询」。
- **记录已处理时不会高亮**：例如刚补完估值再点同一条缺口，列表里已经没有匹配行——此时不高亮是正确行为，但用户可能疑惑，属于可接受的降级。
