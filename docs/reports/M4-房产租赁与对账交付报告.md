# M4 房产租赁 + 对账 交付报告

交付日期：2026-10-16
依据：《18》§4 顺序 6/7、《19》§3 M4、《06》§5/§9、《15》§3.3、《02》§2、《10》§1、《11》§2、《23》§4。

---

## 1. 模块目标与不包含内容

**目标**：房产租赁（租约、租金应收/实收、押金、逾期）+ 账户对账（系统余额核对、差异、调整事件）。

**不包含**（对应后续模块）：
- 租赁逾期提醒推送 → M8 提醒与通知增强；
- 租赁 AI 催收草稿 → M7 本地/第三方 AI；
- 智能录入识别租金账单 → M5；
- 附件上传 → M5（租约附件字段已预留，见 §7）。

---

## 2. 数据表与迁移

新增 3 张表（迁移 `0005`，可升级/回退/重复）：

| 表 | 说明 |
|---|---|
| `leases` | 租约：房产、租客、联系方式、租赁用途、月租、付款周期、币种、起租/到期日、押金、收款账户、物业维修承担方、提醒规则、状态 |
| `lease_receivables` | 租金应收：账期、应付日、金额、状态（pending/paid，逾期派生）、已收金额、关联事件 |
| `lease_deposits` | 押金：金额、状态（held/returned）、收取/退还日期 |

`real_estates` 增加 3 个出租摘要字段（15 §3.3）：`has_lease`、`current_lease_id`、`vacancy_start_date`。

新增枚举：`receivable_status`、`deposit_status`、`repair_bearer`；`source_method` 增加 `reconciliation`（对账调整）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/ledger/leases` | 租约列表 / 新建（`view=properties` 返回房产列表） |

## 4. 关键口径（测试锁死）

1. **应收不改变账户余额**：`rent_receivable` 事件确认后不生成资金变动（06 §9）。
2. **实收计入收入**：`rent_received` 进入 `INCOME_EVENT_TYPES`，确认后账户转入 + 收入统计增加。
3. **押金不计收支**：`deposit_receive`/`deposit_return` 只改变账户余额，不进入收入/支出统计；押金单独显示为待退还资金。
4. **逾期派生**：未收且应付日早于当日即逾期，不入库、无后台任务。
5. **对账不覆盖系统余额**：差额通过「对账调整事件」（income/expense，source=reconciliation）确认后由资金变动对齐；差额为 0 仅更新 `last_reconciled_at`。
6. **终止租约**：一次性确认令牌 + 必填原因；房产同步转空置并记录空置开始日。

## 5. 统计与联动

- 工作台 `summaries.leases` 填充：收租率、应收待收、逾期金额、押金待退还、即将到期租约数。
- 资产详情「租赁」摘要：`has_lease` / `current_lease_id` / `vacancy_start_date`，房产租赁列表复用 `real_estates`（不建第二套 properties 主数据）。

## 7. 已知限制与下一模块依赖

1. **租约附件**：`attachment_id` 字段已预留，上传能力随 M5 智能录入 + 附件安全一并交付。
2. **逾期提醒/催收**：依赖 M8 提醒 + M7 AI。
3. **对账「未匹配流水」**：当前返回该账户截止日前的全部已确认事件供人工比对；"自动识别疑似重复/漏记"属 AI 能力（09 §42），随 M7 接入。
4. **M4 顺带修复了上一轮审计遗留**：无（审计的 O1「草稿编辑/取消」与 O6「贵金属损益」等仍待排期，见《V2.1-阶段性审计报告》）。
