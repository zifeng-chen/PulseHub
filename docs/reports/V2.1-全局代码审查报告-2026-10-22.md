# V2.1 全局代码审查报告

- 审查时间：2026-10-22
- 审查对象：`backend/app`（80 个 Python 文件，25,544 行）、`backend/alembic/versions`（46 个迁移）、`frontend/src`（100 个 Vue/TS 文件，27,745 行）
- 审查方式：静态扫描 + 核心链路逐行阅读 + 业务服务/前端/模型迁移三路并行审查 + 关键结论逐条回读验证
- 结论口径：只列**能在代码中确证**的问题；标注了影响面，不含风格与格式建议

## 一、总体结论

| 级别 | 数量 | 说明 |
|---|---|---|
| P0 阻塞 | 5 | 会造成数据错误、账实不符或功能直接不可用，建议一周内修 |
| P1 重要 | 19 | 权限缺口、时间口径、并发与前端竞态，应在下个迭代内处理 |
| P2 建议 | 14 | 约束/索引/类型/性能加固，可排期 |

代码整体质量高于同类个人项目：统一响应信封、统一异常处理、金额走 `Numeric` + `fmt_amount`、业务时间有专门的 `timeutil`、写接口有幂等基座、前端无 `v-html`/`innerHTML`、生产环境强制密钥自检且关闭 docs。**主要风险不在"写错"，而在"同一件事存在两套口径"**：业务时间有的地方用 `local_now()`、有的地方用 UTC；金额有的走 Decimal、有的先转 float；应收本金有的看 `>0`、有的看 `is None`。

## 二、P0 阻塞（建议优先修）

### P0-1 租约编辑必然失败，且改过一次后永久无法再编辑

- 位置：`frontend/src/views/ledger/LeasesView.vue:128-142`、`:180`；后端 `backend/app/services/leases.py:505`
- 证据：`editingVersion = ref(1)` 只在提交时读取（`:165`），`openEdit` 从未写入 `row.version`；后端 `update_lease` 对 `payload.version` 做乐观锁校验。
- 影响：任何 `version != 1` 的租约点「保存修改」都会 409 VERSION_CONFLICT；成功保存一次后版本 +1，之后再也改不了。
- 修复：`openEdit` 中补 `editingVersion.value = row.version`，保存成功后用响应体回写版本。

### P0-2 纯利息回款被当作全额本金冲减

- 位置：`backend/app/services/receivables.py:226-228`、`:461`
- 证据：`total += part if part > 0 else _dec(amount)`，无法区分「历史记录没有拆分字段」与「本笔明确 `principal_part = 0`（先息后本、只收利息）」。
- 影响：应收余额被多减、`asset.current_value` 偏小、分期分摊错位、结清判断提前、`interest_received` 与实际不符。这正是你之前强调"每笔回款才进净资产"的口径被杀掉的地方。
- 修复：改用 `principal_part is None` 判断是否回退到 `amount`；`0` 就是 `0`。历史数据可在迁移时显式回填 `principal_part`。

### P0-3 资产购置事件不校验资金来源账户归属

- 位置：`backend/app/services/assets.py:598-601`
- 证据：只判断 `acquisition.account_id` 非空就继续；对照 `dispose_asset`（`:976-982`）有完整的 household / status / deleted_at / currency 校验。
- 影响：可把已确认资金变动挂到其他家庭、不存在或已停用的账户；账户币种与资产币种不一致时按资产币种写入，购置款不会被真正扣减或扣错账户，形成无法对账的账。
- 修复：复用 `_validate_relations`，或按 dispose 的方式校验归属与状态后再生成事件。

### P0-4 信用卡还款可核销同家庭其他卡或已删除账单，且可超额

- 位置：`backend/app/services/liabilities.py:1363`
- 证据：账单回写只按 `id` 查 + 比 `household_id`，未校验 `bill.card_id` 属于当前卡、未过滤 `deleted_at`、`paid_amount` 不做上限约束。
- 影响：用本卡还款核销他卡账单；重复登记让 `paid_amount` 超过账单金额，本期账单/最低还款状态错乱。
- 修复：经 `card_id` 校验归属、过滤软删除、把 `paid_amount` 限制在 `total_amount` 内。

### P0-5 冲销只回滚资产处置，其余派生态不回滚

- 位置：`backend/app/services/events.py:616`
- 证据：冲销逻辑只处理 `asset_dispose` 恢复资产状态；投资交易（`cash_balance_for / positions_for` 只看 Trade 自身状态）、信用卡 `paid_amount`、`LeaseReceivable.status` 均不看事件状态。
- 影响：事件显示"已冲销"，但持仓、账单已还金额、应收仍在按已确认计入，冲销形同虚设。
- 修复：按事件类型回滚对应派生记录，或把派生计算统一改为"仅统计 confirmed 事件"。

### P0-6（已复核：误报，撤销）修改密码不撤销其他会话

- 复核：`api/v1/auth.py:161-175` 在 `change_password` 之后已调用 `revoke_all_sessions`，并返回 `revoked_sessions`。
- 结论：服务层单看确实没有撤销，但接口层做了，风险不成立，本条撤销。

## 五、做得好的地方

- 统一响应信封与 `AppError` 错误码，前端 `ApiError` 能拿到 `field_errors` 做字段级提示。
- 金额后端统一 `Numeric` + `fmt_amount`，前端 `MoneyText` 统一动画与精度。
- `timeutil` 明确区分业务时间（本地墙钟）/ 系统时间（UTC），只是执行不彻底。
- 写接口幂等有 `scope:household` 隔离与指纹冲突 409，前端 401 重试复用同一个 key。
- 生产环境强制密钥长度自检、关闭 docs、维护模式中间件、审计日志。
- 前端零 `v-html` / `innerHTML`，无 `eval`，无硬编码密钥；`vue-tsc --noEmit` 通过。
- 39 个后端测试文件、242+ 项测试通过（部署时执行），关键路径有覆盖。
