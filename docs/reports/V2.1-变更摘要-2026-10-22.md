## 1. 数据正确性（批次 1）

### C-01 租约编辑必然 409

- **文件**：`frontend/src/views/ledger/LeasesView.vue`
- **函数**：`openEdit()`（约 128 行）、`save()`（约 165 行）
- **改前**：
  - `const editingVersion = ref(1)` 初始化后从未被重新赋值；
  - `openEdit` 只填表单字段，不写 `editingVersion`；
  - `save` 提交 `version: editingVersion.value`，永远是 1；
  - `Lease` 接口没有 `note` 字段，`openEdit` 把备注固定写成 `''`。
- **改后**：
  - `openEdit` 增加 `editingVersion.value = row.version ?? 1`；
  - `Lease` 接口补 `note: string | null`；
  - `openEdit` 回填 `note: row.note || ''`。
- **影响**：任何 `version != 1` 的租约点保存都会 409 VERSION_CONFLICT，且改过一次后版本 +1，永久无法再编辑。修复后恢复正常。
- **验证**：`vite build` 通过；用户当前无租约数据，未做真机编辑验证。

### C-02 纯利息回款被当成全额本金

- **文件**：`backend/app/services/receivables.py`
- **新增函数**：`principal_of(amount, principal_part, interest_part)`（424 行）
- **改动点**：
  - `repaid_total()`（约 220 行）：查询从 2 列扩到 3 列（补 `interest_part`），累加改调 `principal_of`；
  - `_period_spans()`（约 476 行）：`_dec(r.principal_part or r.amount)` 改为 `principal_of(...)`。
- **改前**：
  - `total += part if part > 0 else _dec(amount)`；
  - `principal_part or amount` 会把 `Decimal("0")` 当假值回退成全额；
  - 结果：先息后本、只收利息的回款被当作整笔本金冲减应收。
- **改后**：
  - 仅当「本金 = 0 且利息 = 0」时视为历史未拆分记录，整笔算本金；
  - 明确拆分的 `principal_part = 0` 保留为 0。
- **影响面**：应收余额、`asset.current_value`、分期分摊、结清判断、`interest_received`。
- **验证**：新增 `test_principal_of_interest_only_repayment`（纯利息 / 本息拆分 / 历史三零三种情形）；应收相关 42 项通过。

### C-03 购置事件不校验资金来源账户

- **文件**：`backend/app/services/assets.py`
- **函数**：`create_asset()`（约 599 行起）
- **改前**：只判断 `acquisition.account_id` 非空就继续生成确认事件与资金变动。
- **改后**：查 `Account`，依次校验：
  1. 账户存在且 `household_id == user.household_id`；
  2. `status == "active"`；
  3. 错误挂到 `field_errors["acquisition.account_id"]`。
- **影响**：可把资金变动挂到其他家庭/停用/不存在的账户，导致账户余额与流水无法对账。

### C-04 信用卡还款可核销他卡账单、可超额

- **文件**：`backend/app/services/liabilities.py`
- **函数**：`add_repayment()`（账单回写段，约 1362 行起）
- **改前**：
  ```python
  bill = select(CreditCardBill).where(CreditCardBill.id == payload["bill_id"])
  if bill is not None and bill.household_id == liability.household_id:
      bill.paid_amount = _money4(_dec(bill.paid_amount) + amount)
  ```
- **改后**：
  1. 查询加 `deleted_at.is_(None)`；
  2. 经 `CreditCard.liability_id == liability.id` 找到卡实体，再比对 `bill.card_id == card.id`；
  3. `paid_amount = min(total_amount, paid_amount + amount)`，多还部分不写进账单。
- **过程记录**：首版误用 `liability.id` 直接比对 `bill.card_id`，被 `test_m3_finance` 的信用卡用例抓出 400，已修正为经 `CreditCard` 关联。
- **影响**：可用本卡还款核销同家庭其他卡、已删除账单；重复登记让已还金额超过账单金额。

### C-05 冲销不回滚派生记录

- **文件**：`backend/app/services/events.py`
- **函数**：`reverse_event()`（资产处置分支之后，约 615-690 行）
- **新增三段回滚**：
  1. **投资**：`InvestmentTrade.event_id == event.id` 且 `status == "confirmed"` → `status = "reversed"`；
     - 持仓 `positions_for` 与资金 `cash_balance_for` 都只统计 confirmed，自动回滚。
  2. **租赁**：`LeaseReceivable.event_id == event.id` → `status="pending"`、`paid_at=None`、`paid_amount=0`、`event_id=None`。
  3. **负债还款**：`LiabilityRepayment` 的 `principal_event_id` 或 `interest_event_id` 命中 → 对应 `CreditCardBill.paid_amount` 减去还款金额，下限 0，`version += 1`。
- **说明（重要）**：负债剩余本金不用额外回滚。`liabilities.outstanding_for` 的算法是「建档剩余 + 已确认 EventMovement 净额」，已 join `BusinessEvent.status == confirmed`，冲销后自动回滚。
- **残留**：`next_payment_date` / `remaining_periods` 在冲销后不回退（无法判断当时是否推进过期数），未自动处理，建议在冲销弹窗提示人工核对。

### P-06 图表「一帧画完」没有入场动画（实测发现）

- **发现方式**：puppeteer 采样 `.flow-card canvas` 的完整画布哈希，只有 2 个签名（`8066` → `43418`），而同一页面的数字有 9 个中间帧。
- **根因 1**：`ResizeObserver` 首次观察会立即回调一次，原代码无条件 `chart.resize()`，把刚启动的入场动画直接 finish。
- **根因 2**：首帧使用 `replaceMerge` 会跳过入场动画。
- **修复**：
  - `EChart.vue` 记录 `lastWidth/lastHeight`，尺寸变化 <1px 时不调用 `resize()`；
  - 首帧 `setOption(..., { notMerge: true })`，后续才用 `replaceMerge + lazyUpdate`；
  - 主题切换 dispose 后重置 `hasRendered`。
- **验证**：修复后同一采样脚本得到 13–14 个连续签名（`13070 → 19254 → 25510 → … → 43418`），柱状逐帧生长，动画持续约 500–600ms。

### P-08 移动端滚动掉帧（性能降级）

- **现象**：手机上上下滑动页面卡顿、掉帧。
- **基线测量**（390×844、DPR 3、CPU 4× 节流、程序化滚动 1.5s）：**42.0 fps**，页面有 **10 个** `backdrop-filter` 元素，0 long task。
- **开销来源**：
  1. `position: fixed` 的全屏背景 `filter: blur(26px)` + 44s 无限漂移动画，每帧重绘整屏纹理；
  2. 每张卡片 `backdrop-filter: blur(18~20px)`，滚动时持续重新采样背后内容；
  3. 3px 平铺噪点、卡片内 28s 旋转光（`aurora-layer::before` 也有 blur）。
- **修复**（`@media (max-width: 900px), (pointer: coarse)`）：
  - 停掉 `.app-backdrop::before` / `.aurora-layer::before` / `.ambient-blob` 的动画与 `filter`，`will-change: auto`；
  - 隐藏 `.app-backdrop::after` 噪点层；
  - `html body *` 统一关闭 `backdrop-filter`；
  - 卡片与 `.shell-topbar / .mobile-topbar / .bottom-nav / .app-toolbar / .app-tabs` 改用实色半透明底 `--glass-mobile`（浅色 `rgba(255,255,255,.88)`、深色 `rgba(23,31,49,.92)`）。
- **结果**：**61.3 fps**（rAF 上限）、`backdrop-filter` 元素 **0**、仍无 long task。
- **视觉**：背景保留静态柔和渐变，卡片由「透玻璃」变为接近实色，截图见 `.selfcheck/mobile-top.png`、`mobile-mid.png`。
- **说明**：无头浏览器的程序化滚动不等同真机触摸合成，但「去掉 10 个实时模糊层 + 停掉全屏背景动画」的收益在移动端只会更明显。

### P-09 高刷新率（120Hz）适配

- **原理**：Web 侧无法「开启」120Hz。浏览器在支持 ProMotion / 高刷的设备上会自动以更高频率调度 `requestAnimationFrame` 和合成，前提是每帧能在 **8.3ms** 内完成（60Hz 是 16.7ms）。所以高刷不是加一个开关，而是把每帧成本压下来。
- **已做的适配**：
  1. `EChart` 初始化加 `useDirtyRect: true`，每帧只重绘变化区域；
  2. `EChart` 的 `devicePixelRatio` 限制为 `min(DPR, 2)`，避免 3x 屏 + 120Hz 时像素填充成为瓶颈（CSS 330px 的画布从 990px 降到 660px）；
  3. 移动端卡片阴影从 `0 8px 28px` 收到 `0 4px 14px`，减少滚动时的阴影绘制；
  4. 新增 `composables/useRefreshRate.ts`：启动时采样 1.2 秒 rAF 间隔，把实际刷新率写入 `<html data-refresh-rate>`；实测 <50fps 时打 `data-low-fps`，CSS 进一步停装饰层、去阴影保底。
- **验证**（无头 60Hz 环境）：`data-refresh-rate="60"`、`data-low-fps` 未触发、画布 660px（DPR 2）、滚动 61.3fps。真机 120Hz 下该属性应显示 120。
- **限制**：系统省电模式 / 低电量会主动把刷新率锁回 60；iOS Safari 在滚动瞬间可能临时降频，属系统行为，页面无法覆盖。

### P-27 全局修复「点击出现输入光标」（2026-10-24）

**现象**：脉枢台、家庭台账、脉诊、设置几乎所有页面，点击卡片 / 页签 / 列表行后出现文本输入光标（I-beam）或半截蓝色选区；移动端长按还会弹「拷贝 / 查询」菜单。

**原因**：此前只在 `.entity-card`（账户 / 资产 / 租赁卡片）局部加过 `user-select: none`，其余界面全部沿用浏览器默认可选中行为。

**改动**（`frontend/src/styles/base.css`，一次性全局解决，不再逐页打补丁）：

| 规则 | 作用 |
|---|---|
| `* { user-select: none }` | 界面层默认不可选中。用通配符（specificity 0）而非 `body`，保证白名单必然覆盖，同时避开 iOS Safari 上 body 级 none 导致输入框无法聚焦的老问题 |
| `button, a, label, summary, [role=button\|tab\|menuitem\|option\|switch\|checkbox\|radio]` | 额外加 `-webkit-touch-callout: none`，关掉移动端长按菜单 |
| 白名单 `user-select: text` | `input / textarea / select / [contenteditable] / table 全系 / pre / code / .kv / .ai-analysis / .summary / .caliber / .conclusions / .meta / .plain / .pane-sub / .hint / .foot` |

**验证**（NAS 线上拖选实测）：
- 脉枢台卡片区、脉诊卡片与口径区、设置入口卡片、流水筛选区 —— 拖选后**无选区**；
- AI 摘要段落、流水表格文字 —— **仍可正常选中复制**；
- 输入框、下拉、日期控件不受影响；
- `vue-tsc` 通过，已部署。

### P-28 光标只改形态（不禁复制）+ 日期区间改双框（2026-10-24）

**修正 P-27 的过度修复**：`user-select: none` 虽然消灭了 I-beam，但也让全站文字不可选中复制，不符合「要能复制」的要求。

关键认识：**I-beam 光标本质是 `cursor: text`，与「能否选中」是两件独立的事**。所以只改光标形态：

| 规则 | 效果 |
|---|---|
| `body { cursor: default }` | 全站默认箭头，点卡片 / 页签 / 摘要都不再像输入框 |
| `input / textarea / select / [contenteditable] { cursor: text }` | 真正的输入控件保留 I-beam |
| `button / a / summary / [role] { cursor: pointer }` | 可点击元素保留手型 |
| 删除所有 `user-select: none` | `base.css` 的 `*` 规则与白名单、`cards.css` `.entity-card`、`SettingsHomeView .entry` 全部移除，全站文字恢复可选可复制 |

实测：AI 综合摘要光标为箭头，同时**可正常拖选复制**。

**日期区间改双框**（`AppDateRangePicker`）：

- 由「单框显示 `2026-10-01 ~ 2026-10-31`」改为 **`[📅 开始日期] ~ [结束日期]` 两个独立框**；
- 交互：点开始框 → 弹双月日历 → 选日期后弹层不关、焦点自动转结束框 → 再选即完成并关闭；结束早于开始时自动交换；两框各自可单独清除；
- 空值文案从「全部日期」改为「开始日期 / 结束日期」；
- 清除按钮改绝对定位不占布局宽；`.period` 宽度 232 → 286px（流水）、220 → 286px（资产），避免日期被截断成 `2026…`；
- **对外 props / emits 不变**，6 处调用方零改动。

**验证**：流水页选 2026-10-16 ~ 2026-11-23，两框完整显示且各自可清除；`vue-tsc` 通过，已部署。

## 12. 回退与恢复

### 数据库

- 0047、0048 都有可用的 `downgrade`；
- 其余 8 个数据迁移现在会**显式抛错**，表示不可回退；
- 需要整体回退时，使用系统内备份：创建备份 → 恢复预览 → 恢复。备份文件同时包含 `alembic_version`，恢复后版本号与数据一致。

### 代码

- 若把代码回退到 0047 之前的版本，数据库里已是密文：
  - 旧代码的 `mask_id_no` 会把密文当作明文截取前后 6 位，**页面显示乱码但不会崩溃**；
  - 因此回退代码时必须同时用备份恢复数据库，不能只回滚镜像。
- 前端可独立回滚（无数据库耦合）。
