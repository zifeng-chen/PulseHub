# 车险表单修正报告（2026-11-04）

## 摘要

车辆保险的表单是照着**人身险模板**做的：保险公司是自由文本输入框，还带着「被保险人 / 受益人」两个只属于寿险、重疾险、医疗险的概念。车险是财产险，赔付对象是车辆损失本身，这两个字段既无业务含义、也永远不会被填。

本次三处一起改：**保险公司改为下拉选择**（常见产险公司 + 已录保单用过的公司 + 「其他」手填）；**删除被保险人 / 受益人**（前端表单 + 后端接口 + 数据库列）。

---

## 一、问题

| # | 问题 | 表现 |
|---|---|---|
| 1 | 保险公司是自由文本 | 同一家公司会被打成「人保」「中国人民财产保险」「人保财险」多个名字，无法按公司聚合 |
| 2 | 多出「被保险人 / 受益人」 | 车险没有这两个概念；空着像没填完，填了也没意义 |

对照规范 `15 §5.3` 也写了这两个字段 —— 说明是**规范本身照搬人身险**带过来的，不只是实现走偏。

## 二、改动清单

### 前端（`frontend/src/components/asset/AssetDetailDrawer.vue`）

**保险公司下拉**

- 新增 `INSURER_PRESETS`：22 家常见产险主体（人保 / 平安 / 太保三家占大头，其余按规模排列）
- 候选 = 预设 + **已录保单里用过的公司**，避免同一家出现两种写法
- 最后一项「其他（手动填写）」：选中后展开输入框，兼容未收录的中小公司
- 编辑老保单时，若公司名不在候选里，自动回落到「手动填写」并保留原文（不会把已有数据弄丢）

**删除两个字段**

- 表单里的「被保险人 / 受益人」整块移除
- `insuranceForm` 里的 `insured_person` / `beneficiary` 状态、`openInsurance()` 回填、`saveInsurance()` 请求体一并删除

### 后端

| 文件 | 改动 |
|---|---|
| `app/db/models/assets.py` | `VehicleInsurance` 删除 `insured_person` / `beneficiary` 两列定义 |
| `app/services/asset_extensions.py` | `INSURANCE_FIELDS`、`serialize_insurance()`、`_validate_insurance_payload()` 白名单、`create_insurance()` 构造参数全部移除 |
| `alembic/versions/d9e0f1a2b3c4_0054_drop_insurance_person_fields.py` | 新增迁移，`DROP COLUMN` 两列（`downgrade` 可回滚为可空列） |

**为什么直接删列而不是留着不用**：上线前确认 `vehicle_insurances` 共 **0 行**，没有任何数据使用过这两列，删除零风险；留着会让 schema 与业务语义长期不一致，后来者容易再次照着它做人身险功能。

**向后兼容**：老客户端（浏览器缓存着旧版前端）仍可能把这两个键传上来，`_validate_insurance_payload` 只按白名单取值，未知键被静默忽略，不会 500。

## 四、部署踩到的两个坑（已修）

首次部署 API 容器起不来，日志是 `Cycle is detected in revisions`。两个独立问题叠在一起：

1. **revision id 撞车**：初版用了 `c7d8e9f0a1b2`，与 0011（`import_batches_records`）完全同名。alembic 因此报「Revision X is present more than once」并把整条链判成环。改用未被占用的 `d9e0f1a2b3c4`。
   教训：新迁移的 revision 必须先在 `alembic/versions/` 里 grep 一遍；只靠「文件里没有这个名字」不够，老迁移用的是 `revision = '...'` 单引号写法，脚本匹配时容易漏。
2. **NAS 上的旧文件没被删**：把文件改名后，部署脚本同步源码时不删除远端多余文件，于是 NAS 上同时存在 `c7d8..._0054` 和 `d9e0..._0054` 两个 0054，镜像里仍是双份 → 依旧撞车。手动 `rm` 掉旧文件后才恢复正常。
   教训：**重命名/删除迁移文件后，必须同时清理 NAS 上的 `backend/alembic/versions/`**，否则镜像构建会把幽灵文件一起打进去。
