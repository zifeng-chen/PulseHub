# 部署指南

> 目标形态：一台常开的机器（群晖 NAS / 家用服务器）跑 Docker Compose，家庭成员在内网访问。
> 脚本化部署见 `deploy/nas_deploy.py`，本文说明它每一步在做什么，以及手工部署怎么做。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 主机 | x86_64，2 GB 可用内存即可（无 Redis / MQ / ES） |
| Docker | 20.10+ 与 Compose v2 |
| 数据库 | MySQL 8.x（可复用主机上既有实例，但**只使用独立的 `fam` 库**） |
| 端口 | 前端 18080、后端 18000（可改 `docker-compose.yml`；宿主 18080 被占用时用 `FAM_WEB_BIND` 只绑局域网地址，见 §5） |
| 时区 | 建议设为主机本地时区；业务时间按本地墙钟存储，容器内时区不一致会导致月末边界偏移 |

## 2. 手工部署（四步）

```bash
# 1) 环境变量
cp deploy/fam-v21.env.example deploy/fam-v21.env
chmod 600 deploy/fam-v21.env
#   必改：FAM_DATABASE_URL、FAM_JWT_SECRET、FAM_ENCRYPTION_KEY

# 生成密钥
python -c "import secrets;print(secrets.token_urlsafe(48))"        # JWT_SECRET
python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"  # ENCRYPTION_KEY

# 2) 落库（只建库，不建表；表由 alembic 建）
mysql -u root -p < deploy/create_db.sql

# 3) 起服务（容器入口会先跑 alembic upgrade head，失败即退出）
docker compose up -d --build

# 4) 验证
curl -fsS http://127.0.0.1:18000/api/v1/health
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/
```

`FAM_ENCRYPTION_KEY` 一旦用于加密过数据就**不能更换**，否则证件号等加密列无法解密。轮换需先解密再加密，务必先做备份。

## 3. 脚本化部署

```bash
python deploy/nas_deploy.py --step probe     # 探测 SSH / Docker / 数据库可达性
python deploy/nas_deploy.py --step mysql     # 建库（不触碰同实例上其他库）
python deploy/nas_deploy.py --step upload    # 打包上传（排除 node_modules / dist / data / .env）
python deploy/nas_deploy.py --step build     # 远端构建镜像
python deploy/nas_deploy.py --step up        # 起容器
python deploy/nas_deploy.py --step verify    # 健康检查 + 关键接口探活
python deploy/nas_deploy.py --step e2e       # 本地全链路 E2E 门禁
python deploy/nas_deploy.py --step all       # 全流程：先本地 E2E，通过后才继续
```

常用开关：

| 开关 | 作用 |
|---|---|
| `--skip-e2e` | 跳过本地 E2E 门禁。**只在前端或文档改动时使用**；后端改动必须跑 E2E |
| `--no-sync` | 不上传代码，只重建容器（改环境变量后用） |

凭据从 `deploy/.secrets.local` 读取（已 gitignore），不回显、不入日志、不进部署包。该文件格式为 `KEY=VALUE`：

| 键 | 说明 |
|---|---|
| `NAS_HOST` | 目标主机地址（也可用环境变量 `FAM_NAS_HOST` 覆盖） |
| `SSH_USER` / `SSH_PASS` | SSH 账号与密码 |
| `MYSQL_USER` / `MYSQL_PASS` | 数据库账号（应用账号口令由脚本生成） |

脚本里**不写死任何主机地址**，公开仓库里只有占位符。SSH 优先用 `~/.ssh/fam_v21_nas` 私钥，不可用时回退密码登录并自动装公钥；`sudo` 走 `sudo -S` 从标准输入喂密码，因此**不需要改 NAS 的 sudoers**。

> E2E 门禁脚本 `deploy/e2e/*.mjs` 通过 `FAM_PYTHON`（Python 可执行文件）与 `FAM_CHROME`（Chrome 路径）定位本机环境，未设置时回退到 `python` 与 Windows 默认安装路径。

## 4. 升级

```bash
git pull
python deploy/nas_deploy.py --step all      # 迁移 + 重建 + 重启 + 验证
```

需求注意：

- 后端改动必须走 `--step all`，否则容器里还是旧代码。
- 迁移只向前追加，回滚靠备份恢复而不是 `downgrade`（见 `docs/guides/数据备份与恢复-使用说明.md`）。
- 升级前建议在设置页手动创建一次备份，备份会同时快照数据库与附件目录。

## 5. 排障

| 现象 | 排查方向 |
|---|---|
| 页面空白 / 接口 502 | `docker compose ps` 看 fam-api 是否 healthy；`docker logs fam-v21-api --tail 100` |
| 容器反复重启 | 多半是 `alembic upgrade head` 失败或数据库连不上；日志首行会打印失败迁移号 |
| 能登录但数据为空 | 检查 `FAM_DATABASE_URL` 是否指向了另一个库（本地 sqlite 与生产 mysql 混用是最常见原因） |
| 部署脚本卡住很久 | 上一轮 E2E 残留的 5173 / 8000 端口进程占着，先结束再重试 |
| 前端容器起来就退出，`docker inspect` 显示 `ExitCode=128` + `failed to bind host port 0.0.0.0:18080` | 宿主有别的进程占了 18080（NAS 上实测是 qBittorrent WebUI，只绑 `127.0.0.1`）。两种解法：① 停掉/改端口那个服务；② 只把前端绑到局域网地址——在部署目录 `/volume1/docker/fam-v21/.env` 写 `FAM_WEB_BIND=192.168.100.110`，访问地址不变（`.env` 不随部署包上传，不会被覆盖） |
| 中文乱码 | 数据库必须 `utf8mb4`（`create_db.sql` 已指定）；容器与 MySQL 时区不一致也会让日期显示偏一天 |
| 日志里所有请求的 `ip` 都是同一个 `172.x.x.x` | 那是 nginx 容器的地址，不是真实来源。检查 `FAM_TRUSTED_PROXIES` 是否覆盖了 nginx 所在网段（默认 `127.0.0.1,::1,172.16.0.0/12` 已够 Docker 内网）；若 nginx 与后端都用 host 网络，要改成实际网段 |
| 正常使用被 429 「请求过于频繁」 | 看是不是同一个出口 IP 上有多人在用；调大 `FAM_RATE_LIMIT_API_PER_MINUTE`（默认 300/分钟）。**不要**为了省事把 `FAM_TRUSTED_PROXIES` 填成 `192.168.0.0/16`——那样局域网机器能直连 18000 并伪造 `X-Forwarded-For` 绕过限流 |

## 6. 备份与恢复

- 备份内容：数据库逻辑导出 + 附件目录快照 + `database.json` 校验清单（含 sha256）。
- 恢复会先自动做一次 `SAFE` 快照，再覆盖；恢复过程校验 checksum，不一致即中止。
- 建议：备份目录挂到宿主独立卷，并定期拷到另一台机器 —— 备份和原数据在同一块盘上等于没有备份。

详见 `docs/guides/数据备份与恢复-使用说明.md`。
