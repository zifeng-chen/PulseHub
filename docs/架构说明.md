# 架构说明

> 面向要改代码的人。只写「为什么这样设计」和「不能破坏什么」，字段级细节见 `docs/spec/23-开发落地契约与字段字典.md`。

## 1. 整体形态

单体应用，前后端分离部署，两者都跑在同一个 Docker 网络里：

```text
浏览器
  │  HTTP
  ▼
fam-v21-web (Nginx, :18080)      静态资源 + /api 反代
  │
  ▼
fam-v21-api (Uvicorn, :18000)    FastAPI 单体
  │
  ├── MySQL 8.x                  生产（NAS 上既有实例，仅用 fam 库）
  ├── SQLite                     本地开发与自动化测试
  ├── 本地 Ollama / OpenAI 兼容   只读分析
  └── PushPlus                   提醒通知
```

刻意不做的事：微服务、Redis、消息队列、Worker、独立调度器。单家庭规模下，进程内 `asyncio` 定时检查（`due_notify`）足够，多一套基础设施只会多一处故障面。

## 2. 后端分层

```text
app/
├─ main.py              应用装配：中间件、异常处理、路由挂载、启动钩子
├─ api/v1/              HTTP 层：参数校验、鉴权依赖、调用 service、返回 schema
│   ├─ router.py        路由聚合
│   └─ auth/ledger/dashboard/insights/settings/ai/audit/system/setup/health
├─ services/            业务层（41 个）：事务边界、领域规则、审计写入
├─ db/
│   ├─ session.py       异步会话
│   └─ models/          8 个模型文件，67 张表
├─ adapters/            外部能力适配：providers（AI/OCR/PushPlus）+ base 抽象
├─ core/                横切关注点：money / timeutil / crypto / enums / errors / ids / security / context / logging
└─ middleware/          RequestContext（请求上下文）与 maintenance（维护模式）
```

约定：

- **路由不写业务逻辑**。`api/` 只做「校验 → 调 service → 序列化」，所有跨表规则在 `services/`。
- **service 自己开事务**。跨多张表的一次操作必须在一个 `AsyncSession` 事务内完成，且同事务写 `AuditLog`。
- **适配器可插拔**。AI / OCR / 通知都通过 `adapters/base.py` 的抽象暴露，`providers.py` 负责按配置选择实现；没有配置时降级为「不可用」状态而不是抛 500。

## 3. 数据模型分组

| 文件 | 表域 | 代表实体 |
|---|---|---|
| `identity.py` | 身份与家庭 | Household、User、Member、RefreshToken |
| `finance.py` | 账务与金融 | Account、Transaction、Event、EventMovement、Liability、Investment、Category |
| `assets.py` | 资产 | Asset、AssetValuation、AssetExtension（房产/车辆/贵金属/股权…） |
| `business.py` | 业务扩展 | Receivable、RecurringRule、RecurringIncome、EmploymentProfile、Reconciliation |
| `leases.py` | 房产租赁 | Lease、LeasePayment、LeaseDeposit、LeaseContract |
| `capture.py` | 智能录入 | CaptureSession、CaptureItem、OcrResult |
| `config.py` | 配置与能力 | HouseholdSetting、CapabilityConfig、AdapterState |
| `ops.py` | 运维 | AuditLog、BackupRecord、MaintenanceWindow、NotificationJob |

其中**账务事件的建模**是核心：一次业务动作落成一条 `Event` + 若干 `EventMovement`（每笔资金流一个 direction）。所有报表、趋势、对账都从 event/movement 派生，不直接改余额字段；账户余额 = 期初 + movements 汇总。

## 4. 三个不能改坏的口径

### 4.1 金额精度

`app/core/money.py::fmt_amount()` 是唯一出口。家庭 `amount_precision`（默认 2）通过 contextvar 在请求级注入，前端用 `ui.amountPrecision` 同步。

只有**金额**走这套 —— 面积、重量、纯度、产权比例、利率、汇率各自保持业务需要的精度，不要一起截断。

### 4.2 业务时间

- 业务时间（`occurred_at` / `traded_at` / `valued_at` / 期间边界）：**本地墙钟 naive**，统一走 `app/core/timeutil.py` 的 `to_local_naive / local_iso / local_now`。
- 系统时间（`created_at`、审计时间）：UTC，走 `utc_iso`。

统计、趋势、对账、提醒的期间边界必须与业务时间同口径。历史上出现过「业务时间按本地存、统计按 UTC 比」导致月末差一天的 bug，改动这块前先读 `docs/reports/时间口径审查报告.md`。

### 4.3 净资产

```text
净资产 = Σ(资产 × include_in_net_worth) + Σ(账户余额) + Σ(投资市值) − Σ(负债剩余本金)
```

两条容易踩的坑：

1. **信用卡不是负债实体**。信用卡是 `account_type=bank` + `category=信用卡` + `credit_limit` 非空的账户，欠款以负余额表达。若同时在负债模块建一条，就会重复计入。
2. **剩余本金不等于合同金额**。`liabilities.opening_outstanding`（建档剩余本金）优先，`initial_amount` 只表示贷款/合同金额；一切剩余本金计算走 `app/services/liabilities.py::base_outstanding()`。

**存量债权的处理**：建档时即标记 `include_in_net_worth=false` 的资产（典型是直接建账、没有对应现金流出的借出款），资产侧不进净资产；每月回款到账时，账户侧 +X 计入、资产侧 −X 不计入，因此净资产随回款逐月增加。**不要**把这类资产的余额一次性计入净资产 —— 那会让净资产凭空跳增，且此后回款不再反映真实资金流入。

## 5. AI 的边界

| 能做 | 不能做 |
|---|---|
| 只读汇总（净资产、结构、趋势、异常） | 直接写业务表 |
| 生成建议与提示文案 | 未经用户确认修改任何数据 |
| 解析账单/票据文本并给出字段建议 | 默认把家庭数据外发到云端 |

实现上：`services/ai_analysis.py` 只读查询并拼接事实片段；外发前经 `mask_sensitive()` 脱敏（证件号、卡号、手机号）；用户确认后由前端调用**普通业务接口**写入，AI 通道本身没有写权限。

## 6. 数据库迁移

- 命名：`{12位hex}_{4位序号}_{描述}.py`，序号单调递增，当前 52 个版本。
- 只允许向前追加，不改历史迁移。生产环境由容器入口执行 `alembic upgrade head`，失败即退出，不启动半升级系统。
- 种子数据与补数据必须**幂等**（`INSERT ... ON CONFLICT DO NOTHING` 或先查后写）。

## 7. 前端结构

```text
src/
├─ views/        页面：dashboard / ledger / insights / settings / setup / login
├─ components/   通用组件：AppCard、AppDataTable、AppDrawer、AppDatePicker、BrandIcon ...
├─ stores/       Pinia：auth、ui（主题与金额精度）、refs（分类/成员缓存）
├─ api/          按域拆分的请求封装
└─ styles/       设计令牌、玻璃质感与动效
```

两条经验：

- 用组件前先读源码。`AppCard` 的内容槽是 `#extra`（没有 `#actions`），`AppDataTable` 的插槽名等于列 key 且没有内置操作列 —— 这两点曾导致「新增按钮不显示」。
- 日期输入统一用 `AppDatePicker` / `AppDateRangePicker`，不要手写 `YYYY-MM-DD` 文本框。

## 8. 两个页面的分工契约

这是产品层面定死的边界，改动前先确认需求真的变了：

| 页面 | 回答的问题 | 内容约束 |
|---|---|---|
| 脉枢台 `/dashboard/snapshot` | 家里有多少钱 | 金额、趋势、结构占比 |
| 台账总览 `/dashboard/workbench` | 账记得对不对、还差什么 | **整页禁止出现任何合计金额**，只有计数、天数、ok/warn/bad 三档与缺口描述 |

缺口信息正好解释脉枢台数字为何偏低，两页互补而不重复。
