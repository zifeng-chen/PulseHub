# 隐私与数据安全

> 这是一个跑在家里、装着全家资产负债明细的系统。仓库、日志、外发通道是三个最容易漏数据的地方，逐个说明防护。

## 1. 仓库里有什么、没有什么

**没有任何真实家庭数据。** 下列内容全部通过 `.gitignore` 排除：

| 排除项 | 内容 |
|---|---|
| `backend/data/`、`data/` | SQLite 开发库、附件、备份快照 |
| `*.db`、`*.sqlite3` | 任何数据库文件 |
| `deploy/fam-v21.env`、`.secrets.local`、`.env`、`.env.*` | 生产环境变量、SSH 与数据库口令 |
| `*.pem`、`*.key` | 私钥与证书 |
| `deploy/*.log`、`deploy/*.tar.gz` | 部署日志与工程包（可能含明文配置） |
| `.workbuddy/` | 工作区记忆与内部状态 |
| `node_modules/`、`frontend/dist/`、`__pycache__/` | 依赖与构建产物 |

`deploy/fam-v21.env.example` 是**占位符模板**（`__MYSQL_USER__`、`__JWT_SECRET__` 等），可以提交；真实取值只在 `deploy/fam-v21.env` 里，不入库。

测试与示例数据全部为构造值：`张三`、`110101199001011234`、`13800001111`、`北京市朝阳区某某路`。合同样例 `deploy/samples/` 是空白模板与虚构示例。

### 提交前自检

```bash
# 1) 有没有文件被误加进来
git status --short
git ls-files | grep -E "\.(db|sqlite3|env|pem|key|log|tar\.gz)$"

# 2) 有没有混进真实凭据
git grep -nIE "mysql\+aiomysql://[^_]" -- . ':!*.example'
git grep -nIE "(password|secret|token|api[_-]?key)\s*[:=]\s*['\"][A-Za-z0-9+/=]{12,}" -- .

# 3) 有没有真实证件号/卡号/手机号（排除测试文件）
git grep -nIE "[0-9]{17}[0-9Xx]" -- . ':!backend/tests/*'
```

任何一条有输出，先停下来确认再提交。

## 2. 产品层面的敏感字段

| 字段 | 处理方式 |
|---|---|
| 银行卡号 | 只存**后四位**，不落完整卡号 |
| 证件号（借款人 / 承租人） | 独立加密列，`FAM_ENCRYPTION_KEY`（Fernet）加解密；列表与日志一律脱敏 |
| 手机号 | 外发与展示时脱敏为 `138****8888` |
| 密码 | bcrypt 哈希，不可逆 |
| 附件（合同、票据） | 存宿主独立目录，随备份一起快照，不对外直链 |

## 3. 外发通道

只有两条链路可能把数据带出本机，都默认关闭：

1. **AI**：默认使用本地 Ollama，不出网。切换云端模型需要用户显式开启并二次确认；无论本地还是云端，请求前统一经 `mask_sensitive()` 脱敏（证件号、卡号、手机号）。
2. **提醒通知**：PushPlus 只发送「标题 + 摘要」，不发送明细金额与账号。

AI 通道本身**没有写权限** —— 它只能读和给建议，任何改动都要用户在前端确认后走普通业务接口。

## 4. 访问与审计

- 单家庭单租户：登录后只能看到本家庭数据，所有查询强制带 `household_id` 条件。
- 刷新令牌滑动续期（30 天内用过即不掉线）；登录连续失败 5 次锁定 5 分钟。
- 关键操作写 `AuditLog`，含**字段级变更前后差异**；删除与不可逆操作二次确认。
- 维护模式可临时阻断业务写入，用于升级或恢复。

## 5. 密钥管理

| 密钥 | 作用 | 注意 |
|---|---|---|
| `FAM_JWT_SECRET` | 会话签名 | 更换会让所有用户重新登录 |
| `FAM_ENCRYPTION_KEY` | 证件号等字段加解密 | **更换会导致历史数据无法解密**，必须先备份、再迁移重加密 |
| SSH 私钥 `~/.ssh/fam_v21_nas` | 部署免密登录 | 仅本机持有，不入库 |

生产环境启动时若仍使用默认 `FAM_JWT_SECRET` 或未提供 `FAM_ENCRYPTION_KEY`，应视为配置错误。

## 6. 已知的取舍

- 数据是**明文数据库 + 少数加密列**，不是全库加密。整库加密会让备份恢复和排查都变复杂，对家用场景性价比不高；真正的防线是「不暴露到公网 + 宿主磁盘加密」。
- 备份文件包含完整数据库，**同等敏感**。备份目录不要放到共享盘或云同步目录里。
- 服务默认只监听内网端口。如需外网访问，请走 VPN 或反代 + TLS，不要直接把 18080 映射到公网。
