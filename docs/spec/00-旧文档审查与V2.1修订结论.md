# 00 · 旧文档审查与V2.1修订结论

## 1. 已审查材料

审查了 FAM 根目录既有交付文档、上一版 `FAM-V2-全量AI重构开发文档-2026-10-14` 和关系校准文档。以下结论覆盖旧文档中的功能、页面、导航、交互、数据和实施规则。

## 2. 已保留的正确原则

- 从零重构，原项目只作为业务参考。
- Vue3 + MySQL 为主技术路线。
- 一级菜单收敛为工作台、家庭台账、洞察、设置。
- AI贯穿资产、消费、收入、负债、投资、租赁、智能录入和洞察。
- 统一业务事件和资金变动模型。
- 金额使用 `DECIMAL(20,4)`，API金额使用字符串。
- 内部转账、借款、押金、信用卡还款、贷款本金等不应错误计入收入/支出。
- AI只生成回答、分析和待确认建议，正式写入由业务服务完成。

## 3. 发现的问题与本版修正

| 旧问题 | V2.1修正 |
|---|---|
| 智能录入在旧页面清单中接近独立一级页面 | 归入家庭台账内部页，支持全局入口和上下文抽屉 |
| 旧文档残留盘点与后台任务状态机 | 本版彻底删除，不创建相关表、路由和组件 |
| 缺少登录页细节 | 新增高端登录页、登录状态、错误、动画、响应式和安全要求 |
| 缺少首次启动配置 | 新增安装检测、数据库连接、管理员创建、基础设置、AI/OCR/通知测试和完成页 |
| 页面只写模块名，缺少每页结构 | 每一页按目标、布局、组件、字段、状态、动作、AI、动画和验收说明 |
| 关系图不覆盖全流程 | 新增页面关系、领域关系、事件关系、AI关系、启动关系和通知关系图 |
| 视觉规范分散 | 新增统一颜色、字号、间距、组件、动效、图表和无障碍规范 |
| AI只有架构说明 | 新增每个业务页面的AI上下文、问法、输出、确认和失败交互 |
| 设置未覆盖其他用户首次使用 | 首次启动必须能配置数据库和管理员，且所有测试结果可见 |
| 开发AI可能反复询问基础选择 | 本版将默认技术、默认口径、默认页面和降级策略直接固定 |

## 4. 旧文档冲突处理

本目录优先级高于 FAM 根目录和旧版本文档。旧文档中出现的 `/capture`、`/operations`、盘点、后台任务、导出、位置管理均视为废弃，不得实现。

## 5. V2.1完成标准

开发AI只需读取本目录，即可确定：先做什么、页面长什么样、数据如何流转、接口如何分层、AI在哪里接入、用户如何确认、失败如何恢复以及何时算完成。
