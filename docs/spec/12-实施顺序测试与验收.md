# 12 · 实施顺序、测试与验收

## 1. 实施阶段

### 阶段一：框架基座与工程启动

按照《18-框架基座与模块化交付规范》完成全新前后端、数据库迁移、健康检查、安装检测、数据库连接、管理员创建、登录、会话、权限、审计、UI组件、玻璃质感应用壳、四项导航、统一错误和能力适配器接口。基座完成后再进入业务模块。

### 阶段二：应用壳和设计系统

完成Token、组件库、动画、四项导航、权限路由、错误处理和响应式布局。

### 阶段三：核心账务模块

完成分类、账户、资产、事件、资金变动、余额、收入支出转账、对账和净资产。

### 阶段四：资产模块

完成通用资产、不动产、车位、车辆、贵金属、估值和资产事件。

### 阶段五：负债与投资模块

完成负债、房贷、车贷、信用卡、投资账户、持仓、交易和估值。

### 阶段六：房产租赁与对账模块

完成房产租约、应收实收、押金、逾期和账户对账。

### 阶段七：工作台和洞察

完成所有指标、图表、点击下钻、期间筛选、空/错状态和在线AI报告。

### 阶段八：智能录入和AI

完成OCR、模型接入、AI工具、全局助手、页面上下文、建议确认、反馈和审计。

### 阶段九：通知、配置、安全和验收

完成设置页、PushPlus、隐私、安全、成员权限、数据备份恢复、数据质量、主题、中文字段、初始化回归、版本升级、部署运维、附件安全、AI评测、性能和发布检查。

## 2. 验收清单

- 首次打开能检测未初始化并完成数据库、管理员、家庭和提供商配置。
- 初始化完成后公开初始化接口关闭，能正常登录和退出。
- 一级菜单只有四项，无盘点、位置、导出、后台任务入口。
- 每个台账页面有列表、详情、编辑、空、错、加载、权限和确认状态。
- 收入、消费、转账、借款、还款、投资、租赁和押金统计口径正确。
- 四个主题图表支持动画、悬停、点击明细、筛选联动和表格摘要。
- 本地AI可以回答资产、消费、收入、负债、投资、租赁问题。
- AI结果显示数据期间、币种、更新时间和来源。
- OCR结果、分类建议、字段补全和提醒均需用户确认才能形成正式数据。
- 模型断开不影响记账、台账、统计和历史查询。
- PushPlus失败不影响台账内提醒。
- 权限、密钥、审计、越权、重复提交和版本冲突测试通过。
- 没有复制旧项目代码、旧数据库和旧路由。
- 基座验收通过后，模块按顺序逐个交付，不允许跨模块大范围返工。
- 每个模块均有独立迁移、API、页面、关系、AI和回归测试。
- 浅色/深色模式切换、全中文字段、统一弹窗、删除二次确认和详细审计在基座阶段通过验收。
- 导航选中状态由路由决定，切换、刷新、深层链接、前进后退和登录跳转都不能固定选中第一个菜单。
- iPhone 16 393×852px 下登录、四项导航、工作台、家庭台账、详情弹窗、AI面板和设置表单可用，且符合安全区和44px触控要求。
- 管理员可以创建备份、验证备份、预览恢复影响并在二次确认后恢复；恢复失败可回滚且有完整审计。
- 数据质量页面可以发现未分类、缺币种、估值过期、关联缺失、重复流水和对账差异，但不能直接修改正式数据。
- 多币种数据保留原始金额、币种、汇率、日期和来源；不同币种默认分组，不能错误相加。
- 升级前有迁移预览和备份，迁移失败不会启动半升级系统。
- 所有接口符合《23-开发落地契约与字段字典》的响应、金额、枚举、版本、幂等和错误码规则。
- 所有模块路由都登记中文标题、一级菜单归属、权限、移动端标题和面包屑，菜单选中状态只能由路由计算。
- 开发、测试、生产配置相互隔离，生产环境没有测试数据和默认密码。
- 附件类型、大小、访问权限和敏感内容检查通过。
- AI固定评测问题集通过，核心金额回答与确定性统计一致。
- 系统进入维护模式时阻止业务写入，维护结束后能恢复访问。

## 3. 测试样例

使用一组包含多成员、多币种、工资、消费、转账、信用卡、贷款本金/利息、投资交易、租金应收/实收/押金、资产估值和异常数据的固定样例。为每个样例准备人工期望值，接口、页面和AI均必须通过对账。

## 4. 每阶段开发AI汇报格式

已完成、变更文件、数据库迁移、接口、页面、测试结果、截图/演示路径、未完成、风险、下一阶段。若与文档冲突必须暂停该项并说明，不得自行扩展范围。
