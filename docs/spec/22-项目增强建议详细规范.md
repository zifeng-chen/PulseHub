# 22 · 项目增强建议详细规范

本文件将项目后续稳定性建议转为必须执行的开发规范。它们不是额外的一级菜单，而是现有四项菜单、框架基座和业务模块中的基础能力。

## 1. 数据备份与恢复

### 1.1 目标

防止误操作、数据库损坏、升级失败和附件丢失。备份用于灾备，不等于用户导出，不提供收入支出报表导出功能。

### 1.2 备份范围

备份必须覆盖：业务表、配置表、用户/权限表、审计表、AI会话和建议、附件索引、附件内容、数据库迁移版本、应用版本、加密密钥版本和备份元数据。

备份元数据：备份编号、创建时间、创建人、数据截止时间、数据库版本、应用版本、迁移版本、文件数量、文件大小、校验值、是否加密、状态和错误原因。

### 1.3 备份流程

管理员进入设置/数据备份 → 查看当前数据库和文件存储状态 → 点击创建备份 → 二次确认 → 生成一致性快照 → 校验表数量和附件数量 → 生成校验值 → 写入备份记录 → 显示完成结果。

基座阶段不实现后台定时备份，不引入Worker和队列；保留手动备份和外部部署系统显式调用接口的能力。

### 1.4 恢复流程

选择备份 → 查看影响范围 → 输入确认短语 → 二次确认 → 锁定写入 → 验证备份完整性 → 恢复数据库和附件 → 执行迁移兼容检查 → 校验关键统计 → 写入恢复审计 → 解除锁定 → 所有用户重新登录。

恢复前必须自动保留当前系统快照；恢复失败必须回滚，不允许系统处于半恢复状态。恢复后要检查：管理员、家庭、账户余额、资产净值、业务事件数量、附件数量、审计数量和迁移版本。

## 2. 数据质量中心

### 2.1 定位

数据质量中心是洞察内部页面，不是盘点，不是库存，也不是后台任务。它帮助用户发现为什么AI分析不完整、统计异常或关联缺失。

### 2.2 质量规则

规则分为完整性、合法性、一致性、关联性、及时性和重复性：

- 完整性：必填字段是否为空。
- 合法性：金额、日期、币种、利率、数量是否符合范围。
- 一致性：账户余额、资金变动、负债余额和净资产是否能对上。
- 关联性：房贷是否关联不动产，车贷是否关联车辆，车位是否关联房产，租金是否关联租约。
- 及时性：估值、保险、合同和账单是否过期。
- 重复性：流水、账单、OCR材料是否疑似重复。

### 2.3 问题等级

严重：会导致净资产、余额或收入支出错误；警告：影响单个模块分析；提示：不影响统计但建议完善。每个问题包含规则编号、对象、字段、发现时间、严重级别、原因、影响范围、建议动作和处理状态。

### 2.4 处理方式

用户点击修复后进入业务详情，或生成AI待确认建议；质量中心本身不能直接修改业务数据。处理状态：待处理、已忽略、已修复、再次出现。忽略必须填写原因并记录审计。

## 3. AI可信度与数据完整性

### 3.1 AI回答必须显示

分析期间、基础币种、数据更新时间、记录数量、已确认数量、草稿数量、排除数据、缺失数据、数据质量问题数量、模型类型、是否调用第三方、脱敏状态、结论类型。

### 3.2 结论分级

- 事实：直接来自确定性统计服务。
- 计算：由确定性规则计算得出。
- 推断：AI根据多个事实归纳，不是确定事实。
- 建议：需要用户判断，不自动执行。

UI必须用中文标签区分四种类型，不能只用颜色。

### 3.3 AI质量保护

当数据质量存在严重问题时，AI回答必须先显示限制说明；数据不足时不得给出看似准确的百分比；跨币种不能合并时必须分组；估值过期时必须标注；没有来源的模型内容不能作为金额事实。

## 4. 多币种底层能力

### 4.1 所有金额字段

业务金额至少保留：原始金额、原始币种、换算金额、基础币种、使用汇率、汇率日期、汇率来源和换算状态。第一版可以只启用人民币，但数据库和API不能假定永远只有一种币种。

### 4.2 统计规则

同币种可以直接汇总；不同币种默认分组；只有存在有效汇率并且用户允许换算时才能生成基础币种汇总。汇率缺失、过期或来源不可信时显示未换算，不得默认为1。

### 4.3 页面表现

金额显示币种代码或中文币种名；混合币种卡片显示“多币种”；图表提供币种筛选；AI回答必须带币种。用户修改基础币种必须二次确认，并记录对历史统计的影响。

## 5. 版本升级和兼容

### 5.1 版本对象

记录应用版本、数据库迁移版本、API版本、前端资源版本、配置版本和AI提示词版本。所有版本变更写入系统审计。

### 5.2 升级流程

升级前检查备份 → 检查数据库版本 → 预览迁移 → 锁定写入 → 执行迁移 → 校验表和关键统计 → 更新版本记录 → 解除锁定。迁移失败必须停止，不允许继续启动半升级系统。

### 5.3 兼容要求

已确认业务事件的含义不可改变；新增字段必须允许旧数据为空并提供迁移说明；删除字段必须先完成数据迁移和审计；API改变必须提供版本或兼容层；模块不能直接依赖未完成模块的内部表。

## 6. 移动端深化建议

### 6.1 核心操作优先级

手机端优先支持查看净资产、快速记账、拍照智能录入、查看提醒、确认AI建议和查看图表；复杂批量编辑、复杂分类树和完整审计可以采用全屏页面。

### 6.2 交互规则

表单使用底部固定提交栏；软键盘打开时自动滚动到当前字段；上传图片支持相机和相册；图表支持长按查看数据点；抽屉改为底部面板；表格改为卡片；危险操作仍使用统一二次确认。

### 6.3 设备能力

允许调用相机、文件选择和剪贴板，但必须明确权限提示；不读取位置，不建设位置功能；图片上传前显示大小和隐私提示。

## 7. 模块化交付质量门槛

每个模块交付包必须附带：模块说明、页面清单、字段字典、数据库迁移、API契约、关联图、权限矩阵、AI矩阵、UI状态清单、移动端检查、主题检查、审计检查、删除确认检查、测试数据、接口测试、页面测试、回归结果和演示路径。

任何一个模块如果缺少“关联图、权限、错误状态、移动端、浅深色、审计或AI边界”，都不能标记为完成。

## 9. 最终建议优先级

P0：框架基座、导航路由状态、主题、中文、统一弹窗、详细审计、删除确认、权限、备份恢复基础、模块接口规范。

P1：核心账务、资产专项类型、负债、投资、租赁、数据质量、多币种基础能力、移动端核心流程。

P2：OCR、AI可信度、第三方AI、洞察图表、提醒通知和复杂移动端体验。

P3：更多AI模型、更多通知提供商、更多资产类型和高级分析主题。
