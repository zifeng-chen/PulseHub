# 21 · V2.1导航与移动端审查结论

审查日期：2026-10-15

## 1. 已确认的问题

旧开发过程中存在一级菜单切换后仍固定第一个菜单选中的问题。本质是导航组件使用了默认索引或静态激活状态，没有以当前路由为唯一来源。

## 2. 已修正的规范

- 一级菜单选中状态必须由当前路由实时派生。
- 禁止永久 `activeIndex = 0` 或初始化后不更新的选中变量。
- 深层路由、刷新、直接访问URL、前进后退、登录跳转、AI来源跳转均要重新计算。
- `/dashboard` 只选中工作台。
- `/ledger/**` 只选中家庭台账。
- `/insights/**` 只选中洞察。
- `/settings/**` 只选中设置。
- 家庭台账二级页面变化不能改变一级菜单结构。
- 桌面侧栏和移动底部导航必须使用同一份路由映射。

## 3. iPhone 16适配基准

首要测试视口：393×852 CSS像素；同时测试 375—430 CSS像素宽度。必须适配顶部刘海安全区、底部 Home Indicator 安全区、系统软键盘、竖屏滚动和触摸操作。

移动端使用四项底部导航，内部业务页使用顶部页签或二级抽屉；不增加一级菜单。点击区域最小 44×44px，底部导航不能覆盖提交按钮和输入框。

## 4. 移动端必须验证的页面

登录、首次启动、工作台、家庭台账总览、资产列表、资产详情、流水列表、表单抽屉、洞察图表、全局AI面板、设置、第三方AI配置、百度OCR配置和通知配置。

## 5. 导航回归用例

1. 打开 `/settings/ai-providers`，设置保持选中。
2. 刷新 `/ledger/liabilities`，家庭台账保持选中。
3. 从资产详情点击洞察，洞察变为选中。
4. 登录成功跳转工作台，工作台选中。
5. 浏览器后退/前进，选中状态跟随路由。
6. 移动端点击洞察后，底部导航只选中洞察。
7. 打开未知路由，不得默认显示第一个菜单选中。
8. 权限重定向后，以最终允许访问的路由显示选中状态。

## 6. 结论

导航路由状态和 iPhone 16 移动端适配已经纳入 M0 框架基座验收，不能留到业务模块阶段处理。
